Quack Weave documentation

Embed MATCH in a standard SQL FROM clause using the SQL/PGQ GRAPH_TABLE operator. Project typed graph rows and join them to DuckDB tables, files, and other SQL relations.

Native test runtime · DuckDB v2.0.1

Build and connect

Build one Quack Weave extension with Ladybug v0.22.3, RelateDB v1.2.0, and Neo4j Aura support. Use DuckDB v2.0.1 on macOS ARM64 or Linux ARM64.

Install Rust, a C++20 compiler, CMake, Python 3.12 or later, and OpenSSL 3 static libraries. Build the extension and start the pinned DuckDB CLI with -unsigned.

make native-deps && make native-release
/path/to/duckdb-v2.0.1 -unsigned

Load the extension once by its absolute path and list the available providers. Then register the graphs you want to query. Provider setup

LOAD '/path/to/quack-weave/build/native/release/extension/quack_weave/quack_weave.duckdb_extension';

SELECT provider_id, setting_name, active_alias
FROM qw_graph_providers()
ORDER BY provider_id;

Each provider has one registration slot per DuckDB instance. Graph aliases are case-insensitive and unique across providers. Use active_alias to inspect routing after concurrent registration or reset.

Query interfaces

SQL/PGQ with GRAPH_TABLE

Use FROM GRAPH_TABLE to name the registered graph and match a supported labeled pattern. Project graph properties with COLUMNS, then apply SQL joins, subqueries, set operations, or aggregates in DuckDB.

WITH watch(route_id) AS (VALUES (101::BIGINT), (104::BIGINT), (101::BIGINT))
SELECT g.route_id, g.destination, g.miles
FROM GRAPH_TABLE (
    air_routes MATCH (o:airport)-[r:route]->(d:airport)
    COLUMNS (r.rid AS route_id, d.code AS destination, r.dist AS miles)
) AS g
JOIN watch USING (route_id)
ORDER BY g.route_id;

DuckDB keeps duplicate joins and UNION ALL rows and applies its usual NULL and scalar-subquery rules. Use an outer ORDER BY for deterministic ordering, and AS MATERIALIZED when multiple references should share one graph result.

Explicit-schema reads with qw_query

Use qw_query in a FROM clause. Supply the columns in graph-result order using BOOLEAN, BIGINT, DOUBLE, or VARCHAR. For Cypher, pass named scalar parameters as a DuckDB STRUCT. SQL aliases can rename the projection.

SELECT destination, miles
FROM qw_query(
    'air_routes', 'cypher',
    $$MATCH (o:airport)-[r:route]->(d:airport)
      WHERE o.code = $origin
      RETURN d.code AS destination, r.dist AS miles$$,
    schema := 'destination VARCHAR, miles BIGINT',
    bindings := {'origin': 'ATL'}
);

The explicit-schema GQL bridge accepts a fixed directed MATCH with labeled nodes and a typed relationship, aliased scalar property projections, and an optional property-to-literal comparison. Use ASCII identifiers and omit the trailing semicolon inside the graph text. GQL parse errors use QW_GQL_PARSE, and valid syntax outside this bridge uses QW_GQL_SUBSET.

Standalone graph reads

Quack Weave binds standalone MATCH to the graph selected on the DuckDB connection. Its default dialect is the supported GQL subset. Set qw_graph_dialect to cypher for Cypher. If a connection predates the extension load, enable the grammar there with CALL add_grammar_extension('quack_weave').

SESSION SET GRAPH air_routes;
SET SESSION qw_graph_dialect = 'cypher';

PREPARE flights AS
MATCH (o:airport)-[r:route]->(d:airport)
WHERE o.code = $origin
RETURN d.code AS destination, r.dist AS miles;

EXECUTE flights(origin := 'ATL');

On the Ladybug path, supported node and relationship values project to DuckDB structures, with identity fields such as _ID, _SRC, and _DST. A supported named path carries ordered _NODES and _RELS lists. The explicit-schema bridge remains scalar.

Provider setup

Choose a unique alias for each graph you register. Use those aliases in GRAPH_TABLE and qw_query.

Ladybug

Register an existing .lbdb file with qw_ladybug_config. Reads reuse the registered read-only database handle and open a connection per scan. Optional timeout_ms and max_batch_bytes values must be positive.

SET GLOBAL qw_ladybug_config = '{"alias":"air_routes","path":"/path/to/air_routes.lbdb"}';

RelateDB

Register a checkpointed single-file .rl bundle. Configure it with qw_relate_config. Registration opens a read-only snapshot and ordinarily discovers node and relationship property types. A declared catalog can supply types for empty or uninferable data. Use node:Label and relationship:Type keys when those identities must be distinguished. RelateDB supports the bridge batch limit, and its configuration rejects timeout_ms with QW_CONFIG.

SET GLOBAL qw_relate_config = '{"alias":"relate_routes","path":"/path/to/routes.rl"}';
SELECT * FROM qw_graph_providers() ORDER BY provider_id;

Give Ladybug and RelateDB different aliases to query both in one DuckDB connection. Before replacing an embedded file, reset the provider registration, replace the file and register it again. Reprepare previously bound queries against the new generation.

Neo4j Aura

Configure the Aura database name and HTTPS origin with qw_neo4j_config. The Query API uses Basic authentication and typed JSON. Enable DuckDB external access and the explicit global remote-read switch. Use a Neo4j identity with effective read-only privileges.

CREATE SECRET routes IN connection (
    TYPE quack_weave_neo4j,
    ORIGIN 'https://example.databases.neo4j.io',
    USERNAME 'graph_reader',
    PASSWORD '<password>'
);
SET GLOBAL qw_enable_remote_graphs = true;
SET GLOBAL qw_neo4j_config = '{
  "alias":"remote_routes",
  "endpoint":"https://example.databases.neo4j.io",
  "database":"neo4j",
  "secret":"routes",
  "timeout_ms":5000,
  "max_response_bytes":1048576,
  "catalog":{"node:airport":{"code":"VARCHAR"}}
}';

SELECT * FROM qw_query(
    'remote_routes', 'cypher', 'RETURN 1 AS id', schema := 'id BIGINT'
);
  • Named secrets. Provision the same secret name on each connection that queries the graph. Each scan resolves it in that connection, checks the secret type and matches the canonical HTTPS origin. Port :443 is equivalent to the default port.
  • Rotation and revocation. CREATE OR REPLACE SECRET routes IN connection (...) affects later scans, including prepared executions. DROP SECRET routes FROM connection or closing the connection removes that credential.
  • Environment references. Alternatively configure "credential_ref":"routes" and the process variables QW_NEO4J_ROUTES_ENDPOINT, QW_NEO4J_ROUTES_USERNAME and QW_NEO4J_ROUTES_PASSWORD. The environment endpoint must equal the registered endpoint. Set exactly one reference field.
  • Remote query interfaces. Use Cypher with an explicit scalar schema or GRAPH_TABLE with a catalog for every projected property. Put selective predicates directly in the Cypher passed to qw_query to reduce the response.

DuckDB's CLI can store literal secret statements in its history. Use your application's credential provisioning path or the environment option for real credentials. DuckDB CREATE SECRET · Neo4j Query API on Aura

Planning and limits

BehaviorWhat to expect
Projection and filtersOn eligible Ladybug and discovered-catalog RelateDB patterns, Quack Weave can fetch only needed properties and send simple graph predicates or small BIGINT equality and IN keys. DuckDB retains the SQL filters.
WatchlistsEligible embedded equality joins can use up to 64 integer keys. A runtime watchlist depends on DuckDB selecting the watchlist as the hash-table build side and producing an exact eligible filter. DuckDB still joins the original rows and keeps duplicates.
AggregatesEligible embedded scalar COUNT(*) and sums can return one graph row. RelateDB's bounded modulo sums require an observed catalog and an accumulator bound. Other forms use DuckDB's aggregation.
Remote graph tablesDuckDB evaluates SQL predicates, joins, and aggregates after the Aura read. Cypher in qw_query can compute the same operation in Aura and return fewer rows.
PlansUse EXPLAIN to inspect eligible graph scans and EXPLAIN (ANALYZE, FORMAT JSON) to inspect rows returned by an executed scan.

Reads are admitted before dispatch. Embedded file reads obey the host external-access policy. Aura reads require both external access and SET GLOBAL qw_enable_remote_graphs = true. RESET GLOBAL qw_enable_remote_graphs disables new remote scans.

An explicit bridge batch budget bounds bridge-owned output, while an Aura response budget bounds the received HTTP body. Embedded engines can still materialize native results. Authored provider queries and explicitly budgeted reads can preserve their original provider evaluation instead of taking an optimizer rewrite.
